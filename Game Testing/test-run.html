Last run: everything passed. A material shows its quality and stats, two batches of one material stay apart, and a Burst Rifle went from the ground to your hands and survived a relog (it came back unequipped, which persistence-4 now tracks).

This run asks one question: can one item carry its own numbers? For graded crafting to matter, a rifle built from good metal has to show better numbers than one built from poor metal. In the 2016 recording of the real game, the server sent some items with their own values. One weapon's damage was 48.7 where the catalogue says 86. The question is whether this game client shows such values in the tooltip, or ignores them and shows the catalogue's.

The new itemattr command rewrites your Burst Rifle's numbers on the wire only. The server doesn't save them, and shooting still does the normal damage. This is about what the tooltip shows.

Start the server on the new build first: ~/Games/PIN/start-pin.sh. Restart the game client too, so it loads the updated /invprobe.

graded-crafting-2-A[ ]The rifle's tooltip shows numbers sent for that one rifle

The Burst Rifle (item 85988) normally reads Damage 8 and Magazine Size 36. This sends it with Damage 99 and Magazine Size 77, everything else unchanged.

grep -aE "item attribute probe" ~/Games/PIN/logs/GameServer.log | tail -5
  • Run 1 (2026-10-12): no difference between the two rifles, but the run couldn't settle it. The server changed only the first rifle it found, so it's unclear which one was hovered, and /invprobe couldn't find either rifle (it compared the id as a number; the game hands it over as text). Now itemattr changes every rifle you hold, the probe compares as text, and the new step 5 redraws the inventory in case the tooltip kept the old numbers.
  • Pass: after step 3 the tooltip reads Damage 99 and Magazine Size 77, and after the last step it's back to 8 and 36. That means one rifle can carry better numbers than another, which is what graded crafting needs.
  • Also a real answer: the tooltip never changes. Then the client draws from its catalogue, and a better batch has to pick a better ready-made version of a part instead. Just note exactly what you saw; I'll read the probe's output from the game's log myself.
